# Install and diagnose

The release workflow builds Linux amd64/arm64, macOS amd64/arm64, and Windows
amd64 archives from the tagged commit. Starting with v0.2.0, download the matching
archive and `SHA256SUMS` from the release page. These assets become available only
after a maintainer publishes the new tag; v0.1.2 has no binary assets.

Verify with `sha256sum --check SHA256SUMS --ignore-missing` on Linux. On macOS use
`shasum -a 256 FILE.tar.gz` and compare it to the exact filename's digest. On
Windows use `Get-FileHash FILE.tar.gz -Algorithm SHA256`. Optionally verify the
GitHub provenance with `gh attestation verify FILE.tar.gz --repo october-dev/moirai`.

Extract using `tar -xzf FILE.tar.gz`, available on modern Windows as well as
macOS/Linux. Put `moirai` / `moirai.exe` in a directory on PATH. Then run:

```sh
moirai version
moirai doctor
moirai list
moirai continue SESSION_ID --from claude_code --with codex --dry-run
moirai continue SESSION_ID --from claude_code --with codex
```

The Go installation path remains:

```sh
go install github.com/october-dev/moirai/cmd/moirai@latest
```

`npm install @october-dev/moirai` installs the TypeScript SDK, not the native CLI.
The release also contains a checksum-derived Homebrew formula (`moirai.rb`), a
standalone Windows executable and winget manifests. The formula and manifests
are generated by `.github/scripts/manifests.mjs` after all platform packages exist.
Homebrew tap and winget community submissions still require publication of the
release URLs and checksums. Until those submissions are made, use the verified
binary archive or Windows executable.

`doctor --json` reports registered capabilities, executable availability and
whether store roots can be opened. It never parses transcripts or probes writes.
`continue --dry-run --json` renders the destination representation without saving,
reserving a session ID in storage, or starting a process. Rendering tests format
compatibility; it cannot prove the destination application's current version
will accept a newly written native session.

## Reproducing packages

From the tagged commit, with Go and Node installed:

```sh
node .github/scripts/package.mjs
```

Set `TARGET_OS` and `TARGET_ARCH` to cross-compile. Outputs include the CLI,
license, Go module build information, an SPDX dependency inventory, and archive SHA-256. The package script
executes the binary on matching native platforms to verify version/capabilities.
Cross-compiled Linux arm64 packages require a separate real-machine smoke test.

## npm trusted publishing

The previous v0.1.2 publish job failed with registry E404/permission denied.
The workflow cannot grant itself npm package permission. Configure the package's
trusted publisher in npm for owner `october-dev`, repository `moirai`, workflow
`release.yml`, matching any configured environment. The workflow requests
`id-token: write` and checks for npm 11.5 or newer. See the official
[trusted publishing instructions](https://docs.npmjs.com/trusted-publishers/).
Use a fresh version tag; npm versions cannot be overwritten.
